## 已验证确认项（17 条）

### FP 类

**F1. 重载方法塌缩为单图节点** · `graph.py:518,570`
`_uid(NODE_FUNCTION, path, fn.name)` / `_uid(NODE_PARAMETER, path, fn.name, pname)`
只用裸函数名，不带行号/重载下标。同文件重载（`setValue(int)`/`setValue(String)`）
共用节点 id，networkx `add_node` 合并属性 → 两个方法塌成一个节点，跨文件边错连、
参数节点互串。`graph.py:540-545` 的 `_fkey(name, line)` 已用 `name$line` 消歧但**只
用于索引不用于节点 id**。修复方向：`_uid` 加 `start_line`（或重载下标）参与。

**F2. 参数合成赋值整函数跨度** · `dataflow.py:156-164,184`
Phase 1.5 为每个参数造合成 `_Assign`，`node=func_node`（整个函数节点），
`def_end_line = 函数末行`。参数「定义」横跨整个函数，RHS→LHS 桥接在
`[起始, 末行]` 区间内把参数桥到无关局部变量；`source=ptext` 含注解
（`@RequestParam String fileName`）时注解/类型名也会被当 RHS 匹配。放大 F 类
遮蔽错配。修复方向：参数 def 只覆盖其真实作用域（参数声明点/函数头）。

**F3. `_word_in_text` 字符串字面量内容当词边界** · `graph.py:232-247`
词边界 `(?<![A-Za-z0-9_$])…(?![A-Za-z0-9_$])` 不识别字符串字面量。实测
`_word_in_text('s','String q = "a s b";')==True`、`_word_in_text('id','"SELECT id
FROM t"')==True` —— 字符串里的字符被当变量引用。RHS→LHS（graph.py:1402）与
var_ref→call_site 桥接据此误连。修复方向：剔除字符串/注释字面量后再判词边界。

**F4. Spring 注解提取三形态不全** · `spring.py:225-244`
按 `_SPRING_METHOD_ANNOTATIONS` 插入序（GetMapping→…→RequestMapping）首个命中
即 return。① 多注解叠加（`@GetMapping`+`@PostMapping` 同方法）只出第一个；②
`method={RequestMethod.GET, RequestMethod.POST}` 数组 `_extract_method_attribute`
split 取最后一个元素；③ 裸 `@RequestMapping`（无 method）走默认。HTTP 方法
提取不完整 → endpoint 方法误标（FP）+ 部分漏（FN）。修复方向：收集全部命中
注解、解析数组、裸 RequestMapping 视为全方法。

**F5. `_handler_has_source` 只查 NODE_ASSIGNMENT** · `discovery.py:359-380`
`if data.get("node_type") != NODE_ASSIGNMENT: continue` —— 只对 assignment 的
source 文本匹配 YAML source 模式，从不查 NODE_PARAMETER。而 Spring/Connexion
handler 最常见的 source 是参数（`mark_params_as_sources` 打在参数节点上）。
纯 `@RequestParam` 处理器被误报 `endpoint_no_source`（默认开启的盲区清单大量
FP）。3 个审查员独立命中。修复方向：`_handler_has_source` 同时检查该 handler
的参数节点是否有 taint_source 标签（或按 source 标签而非文本重匹配）。

**F6. 短属性子串 source 模式过宽** · `taint_rules.yaml:3477` + Python sources
Java `injection_general` 有 7 字符的 `params.`（:3477）；Python sources 有
`.data`（:16）、`.body`（:70）、`.filename`（:72）、`.payload`（:80）。
`_label_taint_nodes`（graph.py:1841-1846）对每个 assignment/call_site 节点取整
条语句文本（`source` / `expression`），经 `match_all_sources`（taint_loader.py:
296-299）纯 `pat in text` 子串打 source 标签。任何名为 `params` 的局部变量/字段
（`params.get/put/set` 全中招）、任何 `.data`/`.body`/`.filename`/`.payload`
属性访问（ORM 行、dataclass、`request.payload`）都被标成污点源 → 大量伪 source
放大候选面。注：NODE_PARAMETER 走 `_classify_parameter_source` 按单参数注解分类，
不受此影响——过宽面是 assignment/call_site。修复方向：source 模式要求更精确
token（如 `request.params[`/`request.params.get(`），或带词边界/限定符匹配。

**F7. pattern_sinks 去重只覆盖 weak_crypto** · `analyzer.py:93-95,406-411`
`_PATTERN_ALIAS_CATEGORIES` 只映射 `weak_crypto→crypto_weakness` 一档，`covered`
去重（406-411）对 `cat` 查 `_PATTERN_ALIAS_CATEGORIES.get(cat, ())`，其余 pattern
型类别拿到空元组 → 永不跳过。而 `MessageDigest.getInstance("MD5"` 同时列在
`crypto_weakness`（taint 型）与 `insecure_hash`（pattern 型）sinks；`new Random(`
/`java.util.Random` 同时列在 `crypto_weakness` 与 `weak_randomness`。节点同时命中
pattern 型与其 taint 型同类 sink 且收到 taint 流时，产出**同节点重复 finding**
（同一弱算法报 crypto_weakness + insecure_hash / weak_randomness 两条）。BUG 49
的注释只处理了 DES 的 weak_crypto 一档。修复方向：把
`insecure_hash→crypto_weakness`、`weak_randomness→crypto_weakness` 补进
`_PATTERN_ALIAS_CATEGORIES`（需回归确认不误伤——`MessageDigest.getInstance("MD5")`
不带 taint 时本就不该有 taint 型 crypto_weakness，pattern 型 insecure_hash 应保留）。

### FN 类

**N1. 位置键去重折叠同函数不同参数 source** · `analyzer.py:319-325`
去重键 `(cat, source.file_path, source.line, ...)`，而参数节点无
`line`/`start_line` 属性，`_node_fields`（683）兜底取 `_line_of(location)` =
函数起始行（graph.py:577 打 `location=函数起始行`）→ **同函数所有参数的
source.line 相同**。两参数流到同一 sink 时去重键塌缩，一条被静默丢弃。
修复方向：去重键加参数名/参数位置（或节点 id）。

**N2. JAX-RS 提取器死代码** · `frameworks/__init__.py:42-54`
`jaxrs.py` 完整实现 `JaxRsExtractor`（@Path/@GET、@PathParam/@QueryParam、
鉴权注解），但 `__init__.py` 只 import/_register 六个框架，从未注册 jaxrs。
JAX-RS 应用接口维度全漏。修复方向：补一行 `_register("jaxrs", JaxRsExtractor)`。

**N3. 源循环早退饿死未出现类别** · `analyzer.py:297-300`
早退条件 `all(c >= max for c in per_category.values())` 只查「已见类别」——
若某类别 source 在 `source_ids` 迭代顺序后面、且前序类别全封顶，break 饿死
未出现类别（该类 finding 归零）。修复方向：检查全部类别
（`per_category.get(cat, 0)` 含 0）。

**N4. `$`-元变量模板模式是死规则** · `taint_rules.yaml` sql_injection sinks
94 条中有 **25 条是 CodeQL 风格模板**（`String $VAR = "$SQLSTR";`、
`(Connection $C).prepareStatement(...).$SQLFUNC(...)`、
`(JdbcTemplate $T).$M($A,...)`、`"$SQLSTR".concat(...)`、`(String $A)` 等），
但全代码库**没有任何模板展开/正则转换**——`match_sink`/`match_all_sinks`
（taint_loader.py:312/323）全是字面子串 `pat in text`，含 `$VAR`/`$SQLSTR` 的
模式对真实代码文本**永远匹配不上**。凡指望这些模板抓住的形态（内联字符串拼接
进 SQL、链式 `prepareStatement(...).$SQLFUNC(...)`、`StringBuilder` 拼接）全部
静默漏报，规则库实际召回远低于表观覆盖。修复方向：删除 25 条死模板，或为模板
实现轻量正则翻译（`$VAR`→`[^;"]+`）——后者需要回归验证真实召回不降。

### 内存类（MEM）

**M1. BFS 路径全量物化** · `analyzer.py:517-574`
`_bfs_to_sink` 把 `results` 全量物化（530），每 sink 存 5 条深度 ≤20 的
(node_path, edge_path) 列表，每次扩张 `[*node_path, succ]`/`[*edge_path, etype]`
整列表拷贝（568/572），**不引用类别预算**（50 在 303 行外层才裁）。稠密可达区
（70k 项目每源达 ~42 sink）单源物化数百条路径 × 数千源 = 峰值内存尖峰。
修复方向：BFS 内早停（预算满即停扩）或懒迭代（yield）。

**M2. 报告序列化全量深拷贝** · `schema.py:300-322`
`to_dict()` 用 `asdict(self)` 深拷贝整个 ScanResult（含全部 findings/链），
`to_json()` 一次性 `json.dumps` 整串再 write_text。3.67M findings 时峰值 =
对象 + 深拷贝 + JSON 字符串三份内存。`to_elements_json` 同样
`[asdict(e) for e in taint_elements]`。修复方向：流式序列化 / 分批 asdict。

### 性能类（T）

**T1. `_collect_taint_elements` 全图节点前置求值** · `analyzer.py:1004-1013`
对全图**每个**节点（含无标签节点）先调 `_node_fields`（683，无 code 时文件读回
兜底 692-693）再判标签。与 T13（模式重扫）叠加。修复方向：先判标签再求值字段，
或按标签索引遍历。

**T2. `_source_files` 无 memo 全量 rglob** · `analyzer.py:1102-1112`
每次 `sorted(self.directory.rglob("*"))` + 逐文件 `is_file()` + `detect_by_extension`，
`_extract_endpoints` 与 `_summarize` 各调一次。70k 文件每次全目录遍历排序。
修复方向：lru_cache 或复用建图阶段的文件清单。

### 缓存类（CACHE）

**C1. 缓存 TOCTOU——建图中途新增文件永久漏扫** · `graph.py:891-899,1011-1014,854`
`add_directory` 的 `index_entries` 在建图开始**一次性物化**（891-899），只有这些
条目进 `add_file` 建图；而写缓存前 `_compute_source_fingerprint(root)` **重新
rglob 整个目录**算当前全量指纹（1011-1014）。若建图期间（分钟–小时级的长时构建）
目录里新增了可识别语言文件（Maven generate-sources 生成 .java、CI 并发、增量
checkout、后台脚本写文件），它**不进图但进存盘指纹**。下次运行指纹相等
（854）→ 直接恢复缓存 → 该文件**永久不被扫描**（确定性缺陷：同一目录两次运行
结果因建图期间外部写文件而不同）。修复方向：指纹基于建图实际使用的
`index_entries`（或建图前后各拍一次清单做差集），而非写缓存时重扫全目录。

**C2. 缓存指纹范围过宽——非扫描语言文件改动即触发全量重建** · `graph.py:497,896`
`_compute_source_fingerprint` 源文件筛选是 `detect_by_extension(entry) is not None`
（497，覆盖**全部已注册语言** java/python/javascript），而建图 `index_entries`
筛选是 `detect_by_extension(entry) in self._parser.providers`（896，**只含本次
`--language` 配置的语言**）。指纹集 ⊋ 图文件集：混合语言仓库按单语言扫描
（`--language java`）时，任意 .py/.js 文件的改动/增删都会使指纹失配 → 每次都
全量重建，缓存形同虚设（性能缺陷，且随仓库语言杂度放大）。修复方向：指纹筛选
条件与 `index_entries` 对齐为 `in self._parser.providers`。

## 外部审查补充（用户转述其他 AI 发现 · 逐条人工验证）

> 2026-08-25 · 4 条外部发现已逐一对照 taint_rules.yaml / analyzer.py / graph.py 验证。

**E1. CodeQL 模板残留裸类型名 sink** —— `Result(`（java/xss）、`Process(`
（java/command_injection）**属实且未删**：CodeQL `$TYPE` 模板被压平成纯字串后，
`List(`/`Object(`/`ResultSet(` 等已由 A 类删除（64c7979），但这两个残留。`File(`
（java/path_traversal）A 类审计有意保留（zip slip/`new File(` 覆盖），但会匹配
`getFile(`/`createFile(`/`deleteFile(` 等方法名子串，**存疑待再审计**。`Validator(`
**不实**——全库唯一匹配是精确 FQN `django.core.validators.URLValidator(`。
`Query(`/`Path(` 存在于 python **sources**（5+1 处），疑似针对 FastAPI `Query()`/
`Path()` 校验器（真用户输入），需实证看匹配面。修复方向：删 `Result(`/`Process(`；
再审计 `File(`；python `Query(`/`Path(` 实证后再定。

**E2. log_injection 泛方法名 sink** —— `['.info(', '.debug(', '.warn(', '.error(',
'.trace(', '.fatal(', '.log(']`（java/log_injection）**属实**：纯子串匹配任何对象
同名方法（`logger.info` 之外的任意 `.info(` 都成 sink），极宽。修复方向：B 类
泛方法名收窄——改为 `logger.info(`/`log.info(`/`LOG.info(` 等带前缀模式，或按
sink 上下文限定；直接删会丢 log_injection 召回，须回归。

**E3. source `.getHeader(` 过宽** —— java sources 多处 `.getHeader(`/`.getHeaders(`
**属实**：纯子串匹配任何对象的 getHeader（`response.getHeader` 设置头也被标成
用户输入源）。修复方向：收窄需兼顾 request 对象变量名不固定（FN 风险），可
考虑排除常见 response/responseHeader 对象，或按参数传递上下文判断。

**E4. BFS 不分 confidence 边** —— `_bfs_to_sink`（analyzer.py:588）只读边类型
不读 `confidence`（graph.py:1178/1195 的 high/medium/low）**属实**：low 兜底全
连接边与 high 参数名匹配边同等扩张 → FP 放大。**修复不能简单砍 low 边**（
full-connect 兜底是铁律保召回用的过近似，砍了会 FN）。正确方向：E 类上下文
敏感桥接——路径优选（有 high 不连 low）或 finding 级置信度排序，而非遍历门控。
