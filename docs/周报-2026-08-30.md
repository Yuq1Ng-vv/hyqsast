# HyqSast 本周进展报告（2026-08-24 ~ 08-30）

> 本周共 **69 个提交**，全部围绕四个主题：**误报治理**、**性能/时间优化**、**噪声降维**、**工具链基础设施**。
> 贯穿始终的硬约束是「缺陷平衡铁律」：**真实漏洞（FN）一条不能丢，误报（FP）能减就减**——每一处收窄都在基准（ant / OWASP / 五项目 A/B）上证明零 TP 损失后落地。

## 一、误报治理（FP 减少）

### 1.1 流敏感重赋值杀毒 —— 本周最大 FP 集群（BUG 152，commit a5de7fa / 39a99f0）

**问题**：ANT 评分最大 FP 集群是「完整度→表达式→基础表达式」FPR 77.3%（17/22 安全样本误报）+ 2 个 flow_sensitive 误报。根因是 def-use 的 `use_locations` 无流敏感截断：`x = <源派生>; x = <固定值>; sink(x)` —— 旧污点穿过重赋值直达 sink。

**修法**：每个 def 的 use 窗口截断到「下一个非自引用、门控上下文严格相同的 def」行。五个护栏保证零 FN：
① 自引用（`x = x + y` / `x += y`）保留链并越过；② 杀毒 def 须与 Di 门控上下文严格相同（含 if 分支位，then/else 互斥不互杀）；③ 反向 use 仅切裸变量重写；④ 字段/容器写不构成杀毒 def；⑤ try 内杀毒 def + catch 内 use 保护。

**中途修一个 FN 回归**（OWASP 丢 2 TP：cmdi 121 / sqli 266）：switch-case 展平后 `_gate_context` 的下降子节点是结构壳 `switch_block`，对所有 case 相同 → default 的 def 顺序杀掉 case 臂的 def。补丁：分支身份下探到互斥的 `switch_block_statement_group` case 臂（39a99f0）。

**战果**（ant sast-java，485 用例）：
| 指标 | 修复前 | 修复后 |
|---|---|---|
| TPR 召回率 | 72.4% (173/239) | **72.4% (173/239)** —— 零 TP 损失 |
| FPR 误报率 | 34.6% (85/246) | **21.5% (53/246)** —— FP 85→53 |

OWASP 回归：TP 1365 / FN 50 与基准逐项一致，零损失。

### 1.3 桥接与常量实参收窄（BUG 65，commit 685dd4a）

ssrf 常量实参假阳性：`_add_cross_function_edges` 的整行 var_ref 过度桥接（如 `HttpRequest.get(url)` 里 `url` 是常量但仍把整行变量当污点源桥接）。收窄桥接条件后，ant 基准确认真实漏洞一条不丢。

### 1.4 误报爆炸诊断 —— 367 万候选归因

用户真实项目 **367 万候选爆炸**，用诊断探针量化三层来源：
- 71ec475：污点候选爆炸诊断探针（三层来源量化）
- 05ca579：探针升级为爆炸定位器（sink 模式命中直方图 + 可达性采样外推）
- 结论（记入 docs/误报面清单.md）：**sink 打标过宽（裸类型名 + 通用方法名）是主凶**，规模乘积是性质，汇总 O(findings×全图) 是性能次凶
- 新增误报面清单 docs/误报面清单.md（A–F 分类归档），E/F 类深挖实锤（返回值桥接跨文件错配、建图期 def-use 遮蔽错配）

### 2.2 污点传播 —— BFS 蝴蝶结爆炸修复（BUG 64，commit 1624991）

**问题**：Return 桥共享化——`function → 所有调用方赋值` 把 BFS 面放大成蝴蝶结，污点传播爆炸。

**修法**：Return 桥去共享化，`call_site → 本调用行赋值` 精确定位。

**战果**：**污点传播 16.9× 提速，OWASP 零损失**。配套把 xAST Benchmark 接入回归基准（0ad751f）+ TP 真伪核查脚本 check_tp.py（e771723）。

### 2.3 污点传播再提速（commit 7207ff9）

sink 反向可达预筛 + BFS 走廊剪枝 + 汇总全图扫描消除——反向 BFS 一次算出「≤20 跳内能到 sink」的节点集，源点不在集内整源跳过，走廊外节点不扩张，语义恒等（BUG 62）。

### 2.4 报告生成 —— canonical 构建 36× 提速（BUG 63，commit 841b8b6）

**问题**：「几百小时」的真凶是 `_build_canonical_findings`，非建图。

**修法**：函数区间 + 位置 memo + `_rel_path` 缓存。

**战果**：**canonical 构建 36×**。实测建图本身是线性（48µs/节点）。

### 2.5 本周收尾 —— BUG 153（commit 0e3b930）

消除 add_file 重复全树遍历：
- graph.add_file step 3 复用 callgraph_builder 已建的 SingleFileCallGraph（省一趟 build_from_tree，**-14%**）

## 三、噪声/复核降维（findings 太多、噪声太多）

### 3.1 消费侧复核降维工具 dedup_findings.py（commit 90df903）
按「源函数 × sink 函数 × vuln_type」归并 finding，把同一批要人工复核的候选折叠成一组，降低人工复核负担。

### 3.2 --vuln-types 定向扫描（commit a5da419）
sink 过滤 + source/sanitizer 全保留，只扫指定漏洞类别；canonical 报告新增 source_function 字段。复核时只跑关心的类别。

### 3.3 uncovered_sink 显式开关（commit 2ef804c）
「未标记危险调用」默认不产出（避免真实项目噪声爆炸），现提供 `scan(uncovered_sinks=True)` 显式开启。顺手把 `html.unescape(` 移出 sanitizer（它是编码不是消毒）。

### 3.4 三份聚合友好报告 JSON（commit a3c0201）
新增 flat / canonical.route / canonical.agg 三种聚合视角，按路由、接口聚合，方便下钻复核。
