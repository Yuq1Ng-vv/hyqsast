# HyqSast 漏报面清单（FN surfaces）

> 2026-08 全量排查。目的：把「一条真实漏洞为什么没被分析出来」的所有可能
> 位置穷举出来，作为后续针对性优化的靶子。每条都标了来源：
> **✅ = 实测确认断链**（demo 样例 ⑥ / `/tmp/fnprobe` 五连探针）、
> **⚙️ = 按代码机制核实**、⚠️ = 推断待实测。

> 姊妹文档：`docs/结构性漏报盲区.md` 收录「确认优化不动/暂缓」的**实测漏报**
> （按项目累积，A–G 分类），与本清单的断点分类（A–I）是两套独立编号。

核心判断：分析器是**确定性、正则/tree-sitter 级、标量变量名级**的污点传播。
漏报的根因几乎都归结为一句话——**污点流经的某一跳不在「变量级 def-use /
同行桥接 / 跨函数边」的建模范围内**。以下是所有已知断点。

---

## A. 对象/容器内部状态写读 —— 整类断链（✅ 实测全断）

数据流只认「标量变量赋值 → 使用」。污点**写进对象内部**（容器 / Builder /
数组 / 字段 / setter）再从**另一处读出来**，链必断：
写侧是表达式语句不建模，读侧只见未污染的宿主变量。

同一根因，五种形态（/tmp/fnprobe 实测 5 端点只有跨函数 return 那条接住）：

| 形态 | 代码 | 断点 |
|---|---|---|
| 容器 | `m.put("k", t); String s = m.get("k")` | demo 样例 ⑥ |
| Builder / 可变累加器 | `sb.append(t); String s = sb.toString()` | 写侧无 LHS 可桥 |
| 数组下标 | `a[0] = t; sink(a[0])` | def 的 var_name 是 `a[0]`，用是 `a`，配不上 |
| setter / getter | `o.setX(t); sink(o.getX())` | 宿主 `o` 从未被标污 |
| `this.field` | `this.buf = t; sink(this.buf)` | 字段写读无别名分析 |

**修法**：把 `put/append/setXxx/arr[i]=` 识别为「写」、`get/getXxx/toString/arr[i]`
识别为「读」，对同一宿主做别名/内部状态传播；`this.field` 按类成员表打通。
参考现状 `graph.py::_add_rhs_to_lhs_edges`——「同行桥接」粒度太粗，跨行/跨语句
都不处理。

---

## B. 调用图解析盲区（⚙️ 机制确定）

- **同名方法 first-wins**：`callgraph_builder.py:219` 多个文件都有 `execute` 时
  只连**第一个**可达候选（`break # first reachable candidate wins`）。危险实现
  排在第二个 → 污点进安全实现 → 真 sink 接不到。
- **未解析调用点整段断链**：`graph.py:747` 只有 `is_resolved` 的 call_site 才建
  arg→param 边。接收者链 / 泛型 / 静态导入歧义解析失败时，`doThing(t)` 这种
  **表达式语句调用**（无 LHS 可被 RHS→LHS 抢救）污点死在调用点 → 函数内 sink 漏。
- **接口 / 多态分派**：`Base b = getImpl(); b.method(t)` 按声明类型解析，命中
  错的实现或无实现。
- **跨包不可达**：Java 跨包类未 import 且不同目录 → 不解析；Python/JS 相对
  导入、`from x import *` 解析不全。
- **依赖 jar 内部方法**：库包装方法内部调 sink 不可见。部分属预期（无法看到
  依赖内部），但 `Commons` / `HttpClient` 等封装层包装真实危险调用时是实打实
  的漏报。

---

## C. 返回值追踪盲区（⚙️ dataflow.py::_trace_return_statements）

- return 追踪只认「标识符 + 赋值中转」（`return x` / `y=x; return y`）。
  `return this.x`、`return arr[0]`、`return sb.toString()` 不追踪。
- caller 侧 return 桥接只在**调用行有 assignment** 时生效（`graph.py:853`
  `callee_function → caller assignment at call line`）：调用点在表达式内部 /
  无 LHS（`if (isOk(t))`）返回值不接回 caller → 下游 sink 接不到。

---

## D. 规则 / 匹配完整性（⚙️ taint_loader.py）—— 最大的实践漏报面

- **未收录的 source/sink API 完全不可见**：子串匹配（`pat in text`），任何不在
  `taint_rules.yaml` / `rules/` 里的调用**连标签都不打**，elements.json 里也没有。
  新框架 / 私有封装 / 新漏洞类都落在这里（`request.newName` 即此）。
- **大小写敏感**：`Request.GetParameter` 之类大小写不符即不命中。
- **sink_excludes 过宽**：正则排除表把真 sink 也排掉 → FN（`graph.py:1162`）。
- 内置 YAML 里 CodeQL 模板噪音（`String(` 等）主要造成误报，但也稀释排查视线。
- 缓解：把 `cpg/discovery.py::find_uncovered_sinks` 做成显式开关（P2 已有条目），
  让「规则表没覆盖的危险调用」也可见。

---

## E. 参数 / 来源标记盲区（⚙️ graph.py::_classify_parameter_source）

- **Spring 隐式绑定**：无注解的简单类型参数（`public String f(String id)`）
  按 @RequestParam 绑定，但分类器只认注解与 `HttpServletRequest` 类型
  （`_PARAM_ANNOTATION_TO_CATEGORY` / `_REQUEST_PARAM_TYPE_HINTS`）→ 不标 source。
- **@ModelAttribute / Body 反序列化对象字段**：整体标 `injection_general`，
  `u.name` 的**字段级**输入依赖 A 类状态写读（断）。
- **source 优先于 sink**：节点同时命中两者只标 source（`graph.py:1150`）——
  若某真实 sink 调用恰好匹配 source 模式，sink 标签被吞。
- **重载签名查表 last-write-wins**：`func_signature_by_name` 按函数名覆盖
  （`graph.py:1101`），重载方法拿错签名 → 注解分类错/漏标。

---

## F. BFS / 枚举截断（⚙️ analyzer.py::_bfs_to_sink）

- **max_depth=20**：链长 >20 步的 sink 永远够不到。
- **max_paths=5**：前 5 条 src→sink 路径填满即停，第 6+ 条路径独有的 sink 漏。
- **max_findings_per_category=50**：单类别截断（P0-2 有 warning 但只提示不补全）。

---

## G. 缓存陈旧（⚙️ graph.py::_cache_path_for / _compute_source_fingerprint）

- 指纹只有 `(相对路径, 文件大小)`：改文件但大小不变 → 复用旧图，新增漏洞
  扫不出来（体感「漏报」）。
- 缓存 key 不含 language / rules：同目录换 language 扫 → 复用错语言图 → 标签全错。
- 修法：指纹加文件 mtime / 内容 hash；key 加 language + rules 集 hash。

---

## H. 行键控桥接对跨行语句（⚠️ 推断待实测）

RHS→LHS / var_ref→call_site 按「location 字符串」精确对齐
（`graph.py:1008`）：跨行语句（拼接续行、多行实参）var_ref 行 ≠
assignment/call_site 行 → 桥接边漏 → 断链。低风险。

---

## I. 多语言缺口（⚙️ languages/__init__.py）

Go / PHP 引擎适配器未实现（规则已备在 `rules/go.yaml`、`rules/php.yaml`）——
整个语言扫不出来；`_detect_language` 自动探测只取主语言，混合语言项目漏扫。

## 建议优先顺序

1. **A 类状态写读** —— 真漏报且最高频。做「写/读」映射（put↔get、
   append↔toString、setXxx↔getXxx、`arr[i]`↔`arr[i]`、`this.field`）
   比字段级污点成本低得多，收益最大。
2. **D + E** —— 规则完整性靠日常补充 + 做 `uncovered_sink` 开关，
   让「规则表没覆盖的调用」也可见。
3. **F + G** —— 纯参数/缓存，顺手。
4. **B / C / H** —— 需要调用图与跨行 AST 改造，放后面。
