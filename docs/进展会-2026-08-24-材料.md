## C. 15-20 分钟口播稿（对着念）

### 0. 开场（~1 分钟）

> 各位好。今天讲的是我负责的这一环——**代码审计 agent 流水线最前面的静态引擎**。
> 我用大概十五分钟讲清楚三件事：**它在这个 agent 里站在哪、我做到了什么程度、下一步干什么**。

### 1. 我在流水线里的位置（~2 分钟）

> 我们整个东西是一个**代码审计 agent**：代码丢进来，自动完成「找洞 → 判真伪 → 写报告」。
> 流水线分三段——`源码 → 静态引擎 → LLM agent → 报告`。**我负责最前面这一段**。
>
> 为什么说这一环重要，四个理由：
> 第一，**我是供料方**。下游 LLM 看到的所有素材——哪些接口暴露、哪些路径可疑、
> 完整的传播链、危险函数源码——全是我产出的。我的质量，决定它判断的起点。
> 第二，**我是唯一结果可复现的环节**。LLM 这次报 3 个、下次报 5 个；我同一份代码
> 永远同一份结果。这给了整个 agent 一个**稳定地基**。
> 第三，**我高召回、宁可多报**。我保证真漏洞一个不漏，报一批可疑项，判定交给它和人工。这是分工。
> 第四，**我便宜、能进 CI**，每次提交都能跑，agent 能拿我的结果做增量审计。
>
> 一句话：**agent 负责聪明的部分，我负责可靠的部分。**

### 2. 为什么静态环必须确定性、零 LLM（~2 分钟）

> 有人会问，为什么不干脆让 LLM 直接扫代码？三个原因：
> **不可复现**——同一份代码结果会漂，没法进 CI，也没法跟它较真；
> **会漏**——LLM 不会逐行把每一条传播路径追完，漏一个真漏洞是静态分析最不能接受的；
> **贵且慢**——每次提交都让大模型全量看一遍，成本扛不住。
>
> 所以我们的分工很清楚：**确定性引擎把候选池圈死，LLM 只在池子上判真伪。**
> 这一环用 tree-sitter 解析语法、用图遍历找传播路径，一个 LLM 都没有，全是纯算法。

### 3. 我产出什么（~2 分钟）

> 我给下游三种结构化产物：
> 一是**接口清单**——路由、方法、参数、有没有鉴权，agent 知道攻击面在哪；
> 二是**候选漏洞**——类型、严重级、完整的 source→sink 调用链，每一步都带文件、行号、源码、边类型；
> 三是**规范化报告**——把危险函数所在函数的**完整源码**带行号拼出来，sink 行标出来。
>
> 每条 finding 还带一个 `endpoint` 字段，直接把漏洞对到具体 HTTP 接口。
> 下游 agent 拿到的是干净的 JSON，**不用再解析代码**，直接开始判真伪。

### 4. 做得怎么样：OWASP 基准（~3 分钟）

> 怎么证明「不漏」？我们用 OWASP Benchmark——业界标准的 Java 漏洞基准，2766 个
> 用例、11 个漏洞类别，每一类都有官方标注的正确答案，是客观标尺。
> [切到表]
>
> 现在的成绩：**总召回 97.2%**，其中 **10 个类别 100%**，包括 SQL 注入、命令注入、
> 路径穿越、加密弱点、XSS 这些主流类型。残余的 40 个漏报全是「弱哈希」这一类的
> 配置驱动用例——算法名写在配置里，运行期才定，静态分析原则上判不了，这是固有边界。
>
> 还有一点想说：我们**误报率 71.8%**。这数字看着难看，但恰恰是**没刷分的证据**——
> 一个往好里做的工具误报率会接近零。我们是「宁可多报也不漏」，真实性问题交给下游。

### 5. 真实项目验证（~2 分钟）

> 基准是标尺，真项目是考场。我们用开源真实项目 **ureport2**（469 个文件、2335 个
> 函数，一个真实的报表引擎）做回归：
> **召回一条不少**——改版前后 272 条关键路径全在；
> **报告干净**——342 条 finding 去重到 272，减掉的全是重复类别合并，没有真漏报。
>
> 另外我们对「开启高召回桥接」做了真实项目验证：开桥接只多 0.6% 的输出，不爆炸；
> 而且新多出来的每一条我们都逐条人工核过——**全是规则宽模式造成的误报，没有一条
> 是漏掉的真实漏洞**。这份较真，是想让你放心：我们的数字是经得起查的。

### 6. 可靠性的工程打磨：一个「较真」的故事（~2 分钟）

> 讲一个具体例子，说明我们怎么打磨可靠性。
> 早先为了补一类漏报，我们加了个「容器桥接」启发式。结果在真实项目上撞墙——
> 一个 383 文件的项目，findings 从 500 涨到 **80 万**。
> 我们没「关了了事」，而是把根因挖出来：一是把普通 setter 误当容器写、二是方法名
> 白名单撞上领域对象。修法是**只认容器类型 + 删掉过宽兜底**。
> 修完效果：OWASP 上 **10 个容器漏报全部恢复**，误报只多了 5 个，输出量从旧版的
> +6000 压到 **+473**。
> 这个故事想说：我们对「不漏报」和「不乱报」是**同一套较真标准**，两边都在管。

### 7. Demo：现场跑一遍（~4 分钟）

> 光讲数字不如看它跑。我们仓库里有一个刻意设计的最小示例 `demo-java`——1 个文件、
> 5 个接口，里面有 4 条真漏洞 + 1 个安全样例。

> 传播路径**，它不需要自己去翻代码找这条链，判真伪就行。

### 8. 诚实的边界（~1.5 分钟）

> 主动把边界讲清楚：第一，**产出是候选清单，不是最终判定**——误报靠下游 agent +

## D. 可能被问的问题（含建议回答）

- **Q：和商业 SAST / CodeQL 官方比，你们强在哪？**
  A：不强在「查得比它们全」，强在**轻、确定性、可复现、能进 CI**；而且是专为
  agent 设计的——输出就是结构化 JSON + 完整调用链，天然给下游 LLM 消费。
- **Q：为什么不用 LLM 直接扫？**
  A：不可复现、会漏（不逐条追传播路径）、贵且慢。静态引擎圈死候选池、LLM 判真伪，
  是成本和召回的最优分工。
- **Q：误报这么多，谁来消化？**
  A：下游 LLM agent 负责判真伪 + 人工复核；规范版报告（sink 完整源码 + 真实调用链）
  把复核成本压到最低；P2 字段级污点、P3 规则清洗会持续降误报。
- **Q：给 agent 的输入长什么样？**
  A：三类产物 JSON——接口清单 / 候选漏洞（含 source→sink 调用链，每步带文件行号源码）/ sink 函数完整源码；每条带 `endpoint` 字段对到 HTTP 接口。
- **Q：97.2% 怎么证明不是刷出来的？**
  A：口径客观——对照 OWASP 官方独立标注逐用例确定性比对；FPR 71.8% 说明没往好里
  刷。TPR 是文件级召回上界，精准性由漏报清单逐条溯源兜底。
- **Q：什么时候能接到 agent 上？**
  A：接口/格式已定（`report.json` / `report.canonical.json` / `report.elements.json`），
  扫描是现成 CLI；对齐下游字段需求和规则清洗是近期主要工作。
- **Q：Go / PHP 什么时候支持？**
  A：规则已备好，缺语言适配器，路线图 P3，想做时很快。

## E. OWASP Benchmark 现场演示（跑全量）

**现场跑全量 2740 个测试用例**，一个一个文件跑、最后汇总评分（per-file 口径：

### E.1 准备（仅 uv sync，基准会自动拉）

```bash

```

> ✅ OWASP Benchmark **不用手动 clone**：`chunk_scan.py` 首次运行检测到缺失会
> 自动 `git clone --depth 1` 到仓库内 `benchmarks/owasp-benchmark/`（gitignore

> `export OWASP_BENCH_DIR=你的路径`（env 优先于默认）。
>
> 🪟 **Windows 注意**：用 **PowerShell** 跑（`$HOME` 可用，cmd 没有）。命令全部是
> 单行——Linux 的行尾 `\` 续行符在 PowerShell/cmd 不生效。扫描已兼容 Windows
> （symlink 无权限时自动退化为复制文件）。若提示 `unrecognized arguments: --per-file`，
> 说明 clone 的是旧版，先 `git pull` 再跑。

> ⚠️ 不要用 `run.py` 做扫描——它默认单进程全量建图，1.6GB 内存会 OOM。现场
> 一律用 `chunk_scan.py --per-file`（内存有界）。

### E.2 现场跑（扫 → 汇总 → 评分）

```bash
cd hyqsast
```

   TP/FN/FP/TN + TPR%/FPR%（官方口径）；

### E.6 断网兜底 / 换平台（通用能力，不只 benchmark）

整个工具都支持离线 + 多平台（linux / win / mac）：

- 依赖打包进仓库内 `vendor/`（gitignored，不随 git 走）：联网机 `uv run python
  scripts/build_vendor.py --all` 一次构建三平台（Windows 也能交叉构建）；
- 离线机只要系统有 python 3.12：`python3 scripts/hyqsast.py <项目> --language java`
  一行跑通用扫描（Windows 用 `python scripts\hyqsast.py ...`）；
- 离线机跑 OWASP 演示需先把基准拷过去：联网机上的 `benchmarks/owasp-benchmark/`
  （240MB）整个拷到同路径，自动 clone 就不会触发。
- 详见 `README.md`「离线执行」节。
