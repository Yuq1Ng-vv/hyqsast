### 24. endpoint 关联增强：source 沿调用链反查 handler

- **来源**：2026-08-26 用户询问「单个 call_chain 怎么匹配接口、会不会该匹配到却匹配不到」时暴露。
- **现状**：`_endpoint_match_for_finding`（analyzer.py:763）只用 source 点 `(file, enclosing_function)` 做三级匹配——source **直接写在 handler 函数体内**才 `exact`；一旦 source 隔着辅助函数（`handler → 调 helper → helper 里取 request 值`，source 的 function 是 helper 名）或跨文件（source 在无接口工具模块、sink 在另一文件 handler 里），就降级 `same_file`（同文件**第一个**接口，多 handler 时可能挂错路由）或 `unmatched`。exact 只覆盖「source 在 handler 体内」这一种情况。调用链明明能走回 handler，但匹配不反向回溯。
- **做法**：从 source 沿调用链反向走 `CALLS` 边找最近的 handler（nx 图 `predecessors` 反向可达），把 `exact` 扩展为「source 可达的 handler」；跨文件链时在整图找。
- **性质**：不改 findings 面（只提升 finding.endpoint 字段质量，供 LLM 下游映射路由），无需铁律回归；需调用图反向遍历数据，待设计验证。
- **连带**：`same_file` 兜底取「同文件第一个接口」在多 handler 文件里会挂到不相干路由——若做本项可顺带按调用链可达性给 same_file 排序。
