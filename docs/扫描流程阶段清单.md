# HyqSast 完整扫描流程阶段清单

> 记录 `uv run hyqsast <项目> --language java -o report.json` 一次完整扫描的
> 全部阶段。所有 stage 名称与进度语义直接对应 `progress.py` / `analyzer.py` /
> `graph.py` 当前代码（对齐 commit e744b1a，BUG 63 封顶之后）。
>
> 用途：排查「进度条卡在哪个阶段」「哪个子阶段最耗时」「各阶段产出对应哪个
> 产物字段」时按图索骥；新增阶段 / 改权重时同步维护本文与
> `progress.py::_PHASE_WEIGHTS`。

## 入口链

`cli.py` → `api.scan()` → `Analyzer.run()`（`analyzer.py:152`）。

进度条分 **4 个主阶段**（`progress.py:24` `PHASES`），总体条按时间权重爬
（`_PHASE_WEIGHTS`），ETA 从同一完成度外推：

| 阶段 | 时间权重 | 性质 |
|---|---|---|
| 建图 | 55.0 | 最重 |
| 接口提取 | 5.0 | 很轻 |
| 污点传播 | 30.0 | 次重 |
| 汇总 | 10.0 | 轻（BUG 62 修复后） |

---

## 阶段 1 · 建图（`graph.py` `add_directory`，`analyzer.py:158`）

`prog.begin("建图")` 后进 `add_directory`，子阶段按序（`graph.py:819-973`）：

1. **校验缓存指纹**（`:819`）——比对缓存指纹；命中则走捷径。
2. **恢复缓存并重标 taint 点**（`:839`，仅缓存命中）——反序列化图 +
   重跑 `_label_taint_nodes` 打 source/sink 标签。
3. **索引文件**（`:854`，`set_total(len(index_entries))` 带粒度）——建
   文件/行/首名三份索引（BUG 50/57/58，`_find_func_node_id` 从全图扫变成
   文件内查）。
4. **跨文件调用边**（`:873`）。
5. **收集跨函数状态槽**（`:878`，`set_total(len(files))`）。
6. **解析源码并建图（含 source/sink 点标记）**（`:895`，`set_total(len(files))`）——
   逐文件 tree-sitter 解析 + CPG 节点 + def-use + taint 打标。**最长子阶段**，
   7 万文件项目的建图大半时间在此循环。
7. **跨文件连边**（`:903`，`set_total(len(cross_edges))`）——参数名匹配
   (high) → 位置匹配 (medium) → 全连接兜底 (low) + 无条件
   call_site→callee→param 桥接（`graph.py:1160-1170`）+ 返回值桥接
   （`:1174-1177`）。**误报面 E 类的主战场**。
8. **写缓存**（`:973`）——命中缓存时此步同时跳过。

## 阶段 2 · 接口提取（`analyzer.py:161`，权重 5，很轻）

1. **提取接口**（`:205`，`set_total(len(files) × len(frameworks))`）——每个
   框架提取器 × 每个文件，`detect` + `extract_routes`。
2. **注入路由参数 source**（`:163`，无进度）——把 `@PathVariable` 等路由
   参数标成污点源。

## 阶段 3 · 污点传播（`analyzer.py:166`，权重 30）

1. **源点前向 BFS**（`:285`，`set_total(len(source_ids))`，**逐 source
   步进**）——先跑 `_sink_reachable` 反向预筛（BUG 62，`analyzer.py:291`），
   R 之外的 source 整源跳过；再对每个 source 前向 BFS（深度 20、每 sink 最多
   5 条路径、类别上限 `max_findings_per_category`），命中 sink 后用 sink 类别
   定 vuln_type。**这就是「污点传播 20 分钟」那段**。
2. **聚合多类别**（`:333`，无进度）——相同 (src,sink) 的多类别候选合并，
   丢弃共存时的 `injection_general` 兜底类别。
3. **pattern 型漏洞**（`:346`，无进度）——非污点流模式（`crypto_weakness`
   等，BFS 永远够不到）。
4. **关联接口**（`:168`，无进度）——finding ↔ endpoint 相互挂接。

## 阶段 4 · 汇总（`analyzer.py:174`，权重 10）

1. **盲区清单**（`:175`，单步）——`_build_blind_spots`（默认只出
   `endpoint_no_source`）。
2. **规范版报告**（`:179`，长循环按工作单元步进）——`_build_canonical_findings`。
   **BUG 62 修掉的旧 O(findings×全图) 就在这**：`_sink_function_block` 全图扫 →
   文件索引、`_render_chain` 的 callee 表每次重建 → `_callee_at_map` 惰性缓存。
   7 万文件项目从「数小时卡 100%」→ 分钟级。
3. **污点元素清单**（`:181`，长循环）——`_collect_taint_elements`。
4. **汇总计数**（`:183`，单步）——`_summarize`。

最后 `prog.end()`（BUG 63：封顶 99.4%，不提前显示 100%/ETA 0:00），返回
`ScanResult` 六个产物（summary / endpoints / findings / blind_spots /
canonical_findings / taint_elements）。

## 大项目时间分布速查

| 主阶段 | 实际占比 | 备注 |
|---|---|---|
| 建图 | 与污点传播各占大头 | 子阶段 6（逐文件解析）是建图主力 |
| 接口提取 | 零头 | — |
| 污点传播 | 与建图相当 | 子阶段 1（逐 source BFS）是污点传播主力 |
| 汇总 | 零头 | BUG 62 修复后 O(findings×全图) → O(全图一次) |

进度条卡点若出现，优先看建图子阶段 6 与污点传播子阶段 1——两个仅有的
`set_total`+逐单元步进的重量级循环。阶段边界的 stage 变更见 `progress.py`：
`begin` 切换主阶段、`stage` 切换子阶段、长循环用 `set_total`+`step` 提供
速度样本供 ETA 外推。
