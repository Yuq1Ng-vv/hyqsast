## 一、一句话定位

**HyqSast 是一个确定性污点分析（SAST）模块**：输入源码目录 + 语言/框架配置，
输出**接口 / 漏洞类型 / 调用链**三类结构化产物。全 tree-sitter（AST）+ NetworkX（图遍历）
+ 子串/正则匹配，**零 LLM**，可在 CI 直接跑。**追求高召回**——产出是「需人工复核的候选」，
不是最终判定，会有误报。

| 维度 | 现状 |
|---|---|
| 支持语言 | java / python / javascript（引擎级） |
| 漏洞类别 | 28 类（`schema.py` SEVERITY_MAP，含 sql_injection/xss/ssrf/path_traversal/xxe/crypto_weakness…） |
| 框架提取器 | spring / jaxrs（java）、flask / django / fastapi / connexion（python）、express（js） |
| 规则库 | `cpg/taint_rules.yaml` ~4600 行，改规则只动 YAML 不动代码 |

---

## 二、两条铁律（所有改动的裁判）

1. **缺陷平衡铁律**：真实漏洞（FN）一条不能丢，误报（FP）能减就减。
   「不增加漏报」≠「不能减少 findings」——只要能证明某条是误报（桥接假连通/跨文件错配/
   宽 sink 误标/遮蔽错配），就该砍。**任何收窄/切断桥接/位置门控改动，必须先过五基准 A/B
   + OWASP 回归证明「真实漏洞零损失」，才落地。**
2. **内存铁律**：本机 ~1.6GB RAM，曾 OOM。跑大型命令前先评估内存：
   OWASP 全量**分块/per-file 扫描**（275 文件/块 × 10）；性能测量用插桩计时
   （`.perf_probe_bench.py`，纯建图无 BFS 无报告写出）；**74MB merged JSON 一次只 load 一份**
   （对比拆脚本单文件加载 + `comm`）。

## 三、架构地图（数据流 + 模块）

**数据流**：`建图 → 提取接口 → 跑污点 → 汇总`

```
CPGGraphBuilder.add_directory → _extract_endpoints → _build_findings → _summarize
```

| 目录/文件 | 职责 | 看什么 |
|---|---|---|
| `src/hyqsast/api.py` | `scan()` 公开门面（薄封装） | 所有配置入口 |
| `src/hyqsast/analyzer.py` | 编排层：建图→接口→污点(BFS)→盲区→汇总 | 核心逻辑在这 |
| `src/hyqsast/schema.py` | 纯 dataclass 数据模型 + SEVERITY_MAP | 6 份报告的字段定义 |
| `src/hyqsast/cli.py` | argparse 命令行入口 | 参数清单 |
| `src/hyqsast/cpg/graph.py` | CPGGraphBuilder：nx.MultiDiGraph + 污点标签 | 打标/桥接/缓存 |
| `src/hyqsast/cpg/taint_rules.yaml` | 规则引擎数据（source/sink/sanitizer） | 改规则只动它 |
| `src/hyqsast/cpg/taint_loader.py` | 规则加载/校验/匹配 | `--vuln-types` 过滤在这 |
| `src/hyqsast/cpg/callgraph*.py` | 单文件/跨文件调用图 + import 解析 | |
| `src/hyqsast/cpg/cfg.py` | CFG + 支配分析 | |
| `src/hyqsast/cpg/frameworks/` | Web 框架路由提取器 | 接口从哪来 |
| `src/hyqsast/cpg/languages/` | 语言适配器注册表 | |
| `src/hyqsast_mcp/` | MCP stdio server（stdout 是 JSON-RPC 信道，不传 progress） | |

**污点传播核心**（`graph.py` / `analyzer.py`）：
- source 只表示「有用户输入」；**精确 vuln_type 由 sink 决定**（BFS 前向命中哪个 sink 类别）。
- 跨函数参数匹配：参数名 → 位置 → 全连接兜底（过近似，保证不漏报）。
- `source 优先于 sink`：节点匹配了 source 就不再评 sink。
- `injection_general` 是兜底类别，与具体类别共存时被丢弃。

**6 份输出报告**（`-o report.json` 自动连带写出）：
主报告 / `.canonical.json`（规范版，人工复核首选）/ `.elements.json`（污点元素清单，排查漏报）/
`.flat.json`（扁平聚合）/ `.canonical.route.json`（接口精简）/ `.canonical.agg.json`（聚合规范）。

## 五、基准与回归体系（怎么证明「没改坏」）

一切收窄落地的闸门，都是这套 A/B：

1. **五基准**：`vfa` / `flask-xss` / `vampi`（python）+ `demo-java`（java）+ 探针样例。
   `benchmarks/baseline_snapshot.py snapshot/compare`，canonical key `(vuln_type, source.file:line, sink.file:line)`，
   **BEFORE ⊆ AFTER = 零损失**（真实漏洞一条不少）。
2. **OWASP 全量回归**（BenchmarkJava，52120 文件）：`--per-file` 分块扫（内存铁律）。
   **基准 `2026-08-25-narrow-batch`：TPR 96.5%（TP 1365 / FN 50），findings 21281**。
   评分客观性口径 + FN 溯源清单见 `docs/OWASP漏报清单.md`。
3. **结果归档**：每轮回归存 `benchmarks/owasp/results/<date>-<label>/`，便于对比。
